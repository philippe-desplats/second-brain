# atlas/maps/

Three kinds of file live here:

- **Live index views** (`{name}.base`), Bases queries rendered by Obsidian. Bases is a core plugin, so they work in a fresh clone with nothing to install.
- **Static indexes** (`{name}-static.md`, `type: note`, `subtype: index`), plain markdown snapshots generated by script, readable by agents and by any editor.
- **MOCs** (`{name}.md`, `type: note`, `subtype: moc`), hand-curated Maps of Content for dense subjects.

## The dual-index pattern

Every index exists as a **pair**, so the workspace stays useful both inside and outside Obsidian. The split is deliberate: a `.base` file is a query and never goes stale, a `-static.md` file is a snapshot and does.

### 1. The live view, `{name}.base`

Pure YAML, no frontmatter. Obsidian renders it as a table, cards, or a list. Because it stores a query rather than a result, it needs no regeneration and cannot drift from the data.

```yaml
filters:
  and:
    - note.type == "client-context"
    - note.status == "active"
properties:
  note.client:
    displayName: Client
  note.last_updated:
    displayName: Last updated
  file.folder:
    displayName: Folder
views:
  - type: table
    name: Active clients
    order:
      - client
      - industry
      - last_updated
      - file.folder
    sort:
      - property: last_updated
        direction: DESC
```

Frontmatter properties are referenced `note.x` in the `properties` and `filters` blocks, and bare in `order` and `sort`. File properties use the `file.` prefix. View types available without installing anything are `table`, `cards` and `list`. A fourth, `map`, needs the Maps plugin and is therefore not used here. The `list` type requires Obsidian 1.10 or later.

**Never label a column with `file.name` in this workspace.** Entity context files are all named `CLAUDE.md` and project briefs are all `README.md`, so the column would read "CLAUDE" on every row. Use the note's own identity property instead: `client` for a client context, `partner` for a partner context, `title` for a project brief, `subject` for an email. Add `file.folder` when the reader needs to know where the note lives.

### 2. The static twin, `{name}-static.md`

Plain markdown table produced by `python3 basic-memory/scripts/generate_indexes.py`. It carries `auto_generated: true` and a do-not-edit banner.

```markdown
---
title: Active clients
type: note
schema_version: 1
subtype: index
date: YYYY-MM-DD
generated: YYYY-MM-DD
auto_generated: true
---

# Active clients

_All clients with status: active in their CLAUDE.md._
_Generated on YYYY-MM-DD by `generate_indexes.py`. Do not edit by hand._

| Client | Path | Last updated |
| --- | --- | --- |
| [[Globex]] | sources/clients/globex/CLAUDE.md | YYYY-MM-DD |
| [[Initech]] | sources/clients/initech/CLAUDE.md | YYYY-MM-DD |
```

**Never edit a `-static.md` by hand.** Rerun `generate_indexes.py` to refresh it. If you leave Obsidian for good, regenerate the statics and delete the `.base` files.

### The one index that has no live view

`decisions-recent` exists only as a static file. It collects `- [decision]` observations from note bodies, and Bases filters on properties rather than on body content. There is no `.base` equivalent, and adding one would mean shipping a view that silently returns nothing.

## The hybrid MOC pattern

A MOC combines a **live Bases view** (for data that changes, like active projects on a topic) with a **manually curated, verified-at-date list** (for the durable narrative the query cannot express). The two coexist in one file, the view as an inline ```base block.

````markdown
## Active projects

```base
filters:
  and:
    - file.inFolder("sources")
    - note.topics.contains("onboarding")
    - note.status == "active"
views:
  - type: table
    name: Active projects
    order:
      - title
      - status
      - last_updated
    sort:
      - property: last_updated
        direction: DESC
```

Manually verified as of YYYY-MM-DD:

- [[Globex Onboarding]], delivered, in follow-up
  - `sources/clients/globex/onboarding/`
````

The "verified as of" date tells a future reader how stale the curated list may be. Refresh it when you revisit the MOC. Full MOC template: `templates/atlas-moc-template.md`.
